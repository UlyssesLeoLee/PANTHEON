## 1. 测试基线与约定

所有测试均为**设计用例，执行状态统一为“未执行”**。环境：Windows 11 x64，8核16GB内存普通SSD；测试数据库使用专用容器或许可证允许的测试实例，绝不指向生产。测试数据包括`customer/orders/order_items`（真实外键）、`legacy_no_pk`（无唯一键）、`unicode_cases`（中/日/Emoji、NULL、二进制、日期、公式前缀）、大表`large_rows`（百万行）、故障注入服务。敏感测试样本均为合成数据。测试报告必须保留构建哈希、客户端/驱动/DB版本、环境与日志证据。

每条用例对应Excel Sheet的完整字段：`测试ID/需求ID/前置条件/步骤/输入/预期结果/类型/优先级/自动化/执行状态/证据`。实际执行时测试者增加执行日期、结果、缺陷ID和证据链接；未执行不得统计为通过。

**判定**：实测与“预期结果”全部一致才通过；遇到实现与规范矛盾标记Blocked并登记缺陷；暂未支持的P1用例不能冒充P0通过。关键安全用例不能被普通缺陷豁免。

## 2. 集成层级、契约与测试环境

1. **UI→Tauri IPC**：类型/序列号/取消/版本冲突/过期事件丢弃。
2. **Tauri→Domain→Driver**：权限/SQL门禁/分页/游标/事务，7个DB版本配置见矩阵。
3. **Domain→SQLite/FS/Vault**：原子保存、密钥不可见、WAL恢复、故障注入。
4. **Domain→AI**：模拟HTTPS服务器，记录发送正文；无同意必须0调用；恶意响应隔离。
5. **Domain→Git/GitGit桥（P1）**：失败不影响本地快照，重试需幂等。
6. **Export/Import→文件系统**：磁盘满、权限错误、取消和目标文件覆盖保护。

**真实DB集成矩阵基线**：PostgreSQL 16、17；MySQL 8.0、8.4；SQLite 3.45或更高受测版本；SQL Server 2019、2022。这里只是设计目标，具体版本支持须在发布前依据实际驱动、DB发行生命周期和官方支持矩阵核准。SQL Server实例授权与客户端连接条件必须合法。TLS拒绝自签证书、无权限、网络半断、会话超时是必须覆盖的负向场景。

## 3. 契约验证要点

- 每条IF都有成功、输入无效、超时、取消、权限不足的适用组合；可用性变化通过`DialectCapabilities`反映。
- 远端DB元数据采集能准确转换成统一类型系统，未支持的列类型不能悄悄丢弃。
- `TxState=UNKNOWN`时Rust一层直接拒绝后续写请求，即使前端重发也不能绕过。
- `metadata_snapshots`的持久化哈希在重启后不变，Schema漂移检测不用时间戳制造假阳性。
- 迁移执行的每条DDL写入单步回执，不假设MySQL/SQL Server/SQLite的DDL与PG同样可回滚。
- AI返回DROP/动态SQL时只得到建议，无IPC执行调用。
