# PANTHEON v0.1 接口契约与数据字典

协议：HTTP JSON，默认 `127.0.0.1:8788`。除 `/health` 外，需要 `Authorization: Bearer <token>`。请求无 Token 返回 401，SQL 违规返回 403，SQLite 错误返回 400。

## GET /health

响应 200：`{"status":"ok","product":"PANTHEON","version":"0.1.0"}`。

## GET /api/schema

响应 200：

```json
{"database":"pantheon-demo.db","tables":[{"name":"users","columns":[{"name":"id","data_type":"INTEGER","not_null":false,"primary_key":true}],"foreign_keys":[]}]}
```

字段：`tables` 为有序表列表；`columns` 包括列名称/类型、SQLite NOT NULL 声明、主键标志；注意 SQLite `INTEGER PRIMARY KEY` 不一定在 `PRAGMA table_info` 的 `notnull` 字段中显式标记为 true；`foreign_keys` 为 from / to_table / to。

## POST /api/query

请求：`{"sql":"SELECT id, name FROM users", "limit":200}`。只允许以 SELECT/WITH/EXPLAIN 开头且 SQLite prepared statement 标记为只读的单条 SQL，禁止参数占位符；服务端限制最多 1000 行，默认 200 行。

成功：`{"columns":["id","name"],"rows":[[1,"Ada"]],"truncated":false}`。Blob 转为 `[BLOB N bytes]` 描述，不透出原始字节。读取超时时返回数据库错误。

## 安全与限制

数据库路径只由服务端启动变量 `PANTHEON_DB_PATH` 指定，用户不能在 HTTP 请求内指定路径或修改数据库。CORS 只允许 `PANTHEON_UI_ORIGIN`，但 CORS 不是身份验证机制。用户输入不得直接进入标识符 SQL；元数据内表名使用双引号转义后进入 PRAGMA 调用。
